# Aurora — адаптация ECLIPSE Ultimate Master Prompt

Дата аудита: 2026-11-04  
База: `main`  
Рабочая ветка: `feature/aurora-village-rework`

## Архитектурное расхождение

Документ `ECLIPSE_Ultimate_Master_Prompt.docx` описывает отдельный проект на Godot 4.x: 3D-сцены, GDScript, изометрическую камеру, 3D Physics и NavigationServer3D.

Текущий `igor74r/magic-rpg` — браузерная RPG на JavaScript и Canvas 2D. В ней уже есть карта, PNG-атласы, движение, коллизии, NPC, квесты, камера и depth-sort. Буквальный перенос требований Godot означал бы миграцию всего проекта на другой движок, а не художественную переработку Авроры.

## Правило адаптации

Для Авроры переносим совместимые художественные и инженерные требования ECLIPSE, сохраняя текущую архитектуру.

- 2D top-down Pixel Art, 16-bit/8-bit детализация.
- Плоские цвета, ограниченная палитра, чёткие края, nearest-neighbour.
- Без blur, градиентной грязи, фотореализма и случайных геометрических заглушек.
- Контрастные стилизованные тени и локальные световые акценты, не разрушающие пиксельную читаемость.
- Единый масштаб пикселя для земли, зданий, props и персонажей.

## Эквиваленты Godot-требований

| ECLIPSE | Текущая реализация |
|---|---|
| Godot scenes / GDScript | ES-модули JavaScript |
| 3D Pixel Art | 2D Pixel Art Canvas 2D |
| Isometric 3D camera | существующая Canvas-камера; ракурс не менять |
| Godot Physics / Area3D | существующие tile/object collision helpers |
| NavigationServer3D | клеточная проходимость и маршруты |
| Resource-based data | data-модули и JSON manifest |
| Pixel-perfect SubViewport | Canvas render scale + nearest-neighbour |
| 3D occlusion | depth-sort по точке основания объекта |
| Godot test scenes | Node/browser smoke tests и визуальные проверки |

## Область работ — только Аврора

Сохранять поведение и идентификаторы: spawn, NPC, диалоги, квесты, торговлю, услуги, Врата миров, Врата Башни, двери, интерактивные зоны, коллизии, маршруты, сохранения, управление, камеру и переходы. Не менять другие локации, боевые системы и сюжет.

Разрешённые визуальные изменения: земля, дорожки, здания, растительность, ограды, уличные props, пиксельные тени, световые акценты и анимации окружения. Графика и физика остаются независимыми данными.

## Кандидат на внешний набор

**Free Pixel Top-down Forest and Village Tileset (16x16), reodesuxz**  
https://reodesuxz.itch.io/free-pixel-top-down-forest-and-village-tileset-16x16

По описанию: 129 тайлов/спрайтов — трава, земля, мощение, дорожные переходы, стены и крыши, двери, окна, деревья, растения, заборы, колодец, телега, фонари, рынок, жители и животные. На странице заявлена бесплатная коммерческая лицензия без обязательной атрибуции; запрещена перепродажа/перераспространение исходного набора как отдельной коллекции.

16×16 — возможная базовая сетка, но совместимость с существующими 96×96/64×64 атласами должна быть проверена на реальных PNG. Архив пока не загружен, его состав и встроенная лицензия не проверены. Не подключать в runtime до проверки палитры, alpha, layout, размеров и прозрачности.

## Этапы реализации

1. Зафиксировать базовый commit и изолированную ветку.
2. Получить и проверить реальные PNG и лицензию набора.
3. Сопоставить ресурсы с текущей сеткой, масштабом и pivot.
4. Подготовить локальные PNG-атласы и обновить manifest.
5. Подключить ресурсы через текущий Canvas renderer с безопасным fallback.
6. Заменять здания и props поэтапно, сохраняя object IDs и коллизии.
7. Проверить маршруты, двери, NPC, интерактивные зоны, depth-sort и загрузку ресурсов.
8. Запустить профильные тесты и браузерные визуальные проверки.
9. Не вливать изменения в `main` до успешной проверки.
